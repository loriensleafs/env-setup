# src/items/claude-code — Claude Code settings, hooks, statusline (ADR-013)

`configure()` writes `~/.claude/settings.json` (backup first) and `~/.claude/hooks/*`. Drive with
`bun src/items/claude-code/.claude/skills/run-src-items-claude-code/driver.ts` (`detect()` and
`buildSettings` on a fixture only).

- Read assets only through `ASSET_PATHS` (`assets-embed.ts`); `import.meta.dir` is ENOENT in the
  compiled binary (broke v0.1.4).
- `settings.json` is generated by `buildSettings`: Dev-directory-templated marketplace path,
  plugins filtered by the repos actually Picked (`PLUGIN_REPO_MAP`) — the template is input, never
  copied verbatim.
- `detect()` deep-compares `settings.json` and all four deployed assets; changing an asset changes
  what Applied means for this item.

## `assets/` — shipped payloads that run on the target machine

Pure Bun with no imports from `src/`; outside the project typecheck. Contracts: `statusline.ts`
JSON stdin → one ANSI line, no trailing newline; `hooks-subagent-statusline.ts`
`{columns, tasks[]}` → one JSON line per overridden row; `hooks-format.ts` FileChanged payload,
project root from `$CLAUDE_PROJECT_DIR`, always exit 0 — and it no-ops silently when Biome's
config errors (OVERVIEW Next-up 5). `hooks-notify.ts` fires a real notification and raises
Ghostty: run it by hand only. `settings.template.json` keeps referencing all four scripts by their
installed names. Fixture driver:
`bun src/items/claude-code/assets/.claude/skills/run-src-items-claude-code-assets/driver.ts`.
