# Sessions — what has been done, session by session

One file per **session** — a bounded stream of work toward one Goal, `open` until `closed`, which
may span any number of conversations (ADR-020). A conversation joins the open session whose Goal
is its work or opens one *before its first commit*; a conversation that changes nothing needs
none. Together the files are the append-only record of every change that reached
`main` — with, for each commit, a Summary, the Why, and a note per touched file — **plus** the
narrative a commit log cannot hold: what was asked, what was tried and abandoned, what was
verified and how. This is the **rehydration mechanism**: `../OVERVIEW.md` says where the project
*is* and what is *next*; these files say what was *done* and *why*, so a new session opens the
right files or `git show <sha>` instead of re-deriving history from the code.

## Rules

### Reading

1. OVERVIEW "Status" and "Next up" first — the summary. Then every **open session** in full
   (the index above shows each session's status): Goal / Outcome / Open at end, the Narrative,
   then the Changes. Then earlier sessions back to the last `> **Released vX.Y.Z**` marker —
   everything after that marker is unreleased.
2. Per entry: `Summary` = what changed, `Why` = the motive, the per-file lines = where and what in
   each file, `Notes` = gotchas. `git show <sha>` only when the exact diff matters.
3. Taking a "Next up" item: `grep -rn <file-or-keyword> docs/sessions/` finds every prior change to
   it, across sessions.

### Writing — continuously, never deferred

The procedure that does all of this is the `/session` skill: `/session start` at the beginning of
a conversation, `/session entry` right after every commit, `/session end` before leaving,
`/session close` when the Goal is done (typed-only aliases `/session-start`, `/session-entry`,
`/session-end`, `/session-close`). The rules below are what the skill enforces and what a human
does by hand.

- **Join or open before the first commit.** `bun run session list` shows every session with
  its status. Join the open one whose Goal is your work (use `--session SES-NNN` from then on), or
  open one: `bun run session new <slug> [--plan "PLAN-NNN · <part>"]` creates
  `SES-<next>-<slug>.md` from the template (H1 `# YYYY-MM-DD HH:MM · Title` records when it
  opened; the number orders sessions; `Status: open`; `Plan:` names the plan and part it serves,
  or `—`). Set the title and `Goal` immediately. A conversation that changes nothing opens none.
- **Your own session, by name.** Another conversation may share this checkout with its own open
  session. `--session SES-NNN` (or just the number) makes `bun run session` append to *your*
  file, `current` list its placeholders by line, `check` gate it and `close` close it; with
  more than one session open the tool refuses to guess. Placeholders in any other session are
  reported as warnings and left to that conversation — never edited to make your gate green.
- **Leave vs close.** Leaving (`/session end`): the log complete, `Open at end` the handoff, the
  session stays open for the next conversation. Closing (`/session close`): the Goal is done,
  `Outcome` written, `bun run session close --session SES-NNN` (it runs the gate first —
  this time counting `Outcome` and `Open at end`, which `check` leaves alone while a session
  is open — and refuses while anything is unfilled or unrecorded) flips `Status: closed`; the plan it served
  gets its status line / ticks citing the shas. Nothing is appended to a closed session; reopen
  one only by editing its Status line, with a dated note in the Narrative saying why.
- **After every commit** (not at the end of the PR, never "later"): `bun run session` appends an
  entry skeleton per commit no session mentions — `Summary` / `Why` placeholders and one line per
  touched file with +/− counts — into the current session. Fill in every `_(fill in)_`: the
  Summary, the Why, and a short phrase per file of what changed in it. Add `Notes` when a future
  reader must know something. `bun run session check` fails while anything is missing or
  unfilled. Commit as `docs(session): …` — those commits are skipped by the script, so they never
  need an entry of their own.
- **Narrative as it happens:** requests, decisions, dead ends, false leads, verifications — write
  them into the Narrative when they happen, citing entries by sha. Update `Outcome` / `Open at
  end` before the session ends. Update OVERVIEW "Status" / "Next up" (and the ADR / PRD section,
  if a decision or requirement moved) in the same step, citing the sha.
- `Files` means **every** file the commit touched, whatever kind — source, tests, docs (these
  files, OVERVIEW, PLAN…), config (`package.json`, `biome.json`, `lefthook.yml`), CI workflows,
  scripts, assets. The script lists them all from git; never trim the list by hand.
- A release (`chore(release): vX.Y.Z` commit + tag) gets a `> **Released vX.Y.Z**` marker after its
  entry; the script inserts it only when that entry is appended — tag first, then `bun run session append --session SES-NNN`; if the entry already exists, add the marker line under it by hand.
- Never rewrite or reorder old entries or old sessions; correct a mistake with a new entry or a
  dated note. Merge PRs with merge commits (not squash) so the shas stay valid.

## Session file template

```markdown
# YYYY-MM-DD HH:MM · Title of the session

- Goal: what this session set out to do
- Status: open | closed
- Plan: PLAN-NNN · the part it serves, or —
- Outcome: what it actually delivered (releases, merged PRs) — written when it closes
- Open at end: the handoff — what the next conversation picks up first, what is unverified

## Narrative

What was asked, decided, tried and abandoned, verified (and how); cite entries by sha.

## Changes (one entry per commit, in order)

### YYYY-MM-DD · type(scope): subject · sha

- Summary: one or two lines — what this change does as a whole
- Why: one line — the problem or request that caused it (name who asked if it was Peter)
- Files:
  - `src/thing.ts` (+12/−3) — what changed in this file
  - `docs/OVERVIEW.md` (+4/−1) — what changed in this file
  - `.github/workflows/ci.yml` (+2/−0) — what changed in this file
- Notes: optional — gotchas, follow-ups, what was verified and how

> **Released vX.Y.Z** — tag on this commit.
```
