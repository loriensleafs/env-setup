## What it is

A pure-Bun macOS environment-setup CLI. One command on a fresh Mac
(`curl -fsSL https://raw.githubusercontent.com/loriensleafs/env-setup/main/install.sh | sh`)
scans the machine, lets the user pick what to install, installs/configures ~65 items (apps,
runtimes, fonts, repos, macOS settings, app configs), then runs the attended finishing steps
(sign-ins, permission grants, license pastes) — and **the same command re-run converges the
machine** (re-detects state, pre-checks what failed last run). `doctor` diffs the machine
against its manifest read-only; `sync` applies the manifest non-interactively; `connect`
re-runs skipped attended steps; `secrets` manages the age-encrypted store.

Owner: Peter Kloss (github loriensleafs). Public repo. Released: v0.1.9 (2026-08-31).

## Hard rules (never violate)

- Pure Bun. No Node runtime, no Python we ship. `node:` builtins are fine (Bun implements them).
- `@clack/*` is vendored from `main` (`vendor/*.tgz`) for `completeOnTab`; never swap to npm.
- Secrets only in `secrets.json.age` (+ password manager). Never a key — even partial — in any
  tracked file or commit message.
- Tests: `<name>.test.ts` in a sibling `__tests__/`. `bun run check` (Biome + tsc + markdownlint)
  must pass; lefthook enforces on commit/push.
- Best way, not easiest: research official docs before choosing an install method; identify and
  install transitive prerequisites automatically.
- Peter's collaboration style: one question at a time (AskUserQuestion), researched options with a
  recommendation, no batched lists; pushback welcome. Real web research, not assumptions — an
  unverified claim (e.g. "no incompatibilities exist") burned trust once; verify or say unverified.

## Architecture

- **Item** (`src/items/item.ts`): `detect`/`install`/`configure`/`verify`, `deps`, `ceremonies`,
  Zod `configSchema` + `defaultConfig`, optional `zsh()` shell contribution. `defineItem`.
  Registry assembled in `src/items/all.ts` (toposorted execution via `deps`).
- **DetectResult**: `installed`, `version`, `satisfies`, **`differs`** (config present but not
  matching our effective defaults). Drift-aware `detect()` on every item with defaults.
- **Reset-on-drift model** (decided 2026-08-27, replaced a conflict-consent design): an item is
  off the install list only if installed at the wanted version AND config exactly matches; drifted
  items show as "installed — settings differ (select to reset)", **unchecked** — selection is the
  consent. No conflict checking. (`CONFIG-COMPAT-PLAN.md`)
- **Manifest** (`src/manifest/`): Zod-versioned, auto-migrated on load (`migrations.ts` has the
  recipe). **Journal** (JSONL): resumable runs, `failedSteps` drive "failed last run — retry".
- **Orchestrator** (`src/orchestrator/`): per-step detect → skip if satisfied; retry once;
  required-item failure aborts; `ItemContext.ask()` lets an item ask a yes/no mid-step (spinner
  pauses). Outcome `deferred` = ceremony-only item.
- **Flow** (`src/commands/bootstrap.ts` → `executePlan`): scan (parallel per section) → identity
  prompts (prefilled from manifest) → picker (`ui/group-multi-select.ts`, requires-cascade) →
  per-item config screens (`ui/config-screens.ts`, one clack `p.group` per item, fields from the
  Zod schema) → confirm → install (append-only spinner per step) → **connect phase runs
  automatically** (`ceremonies/connect-phase.ts`, deduped) → finishing pass.
- **Terminal handling** (`src/ui/terminal.ts`): under `curl | sh` stdin is the exhausted pipe.
  Bun cannot read a shell-redirected `/dev/tty` nor a defineProperty-replaced `process.stdin`;
  the ONLY working path is opening `/dev/tty` in-process and passing it as every prompt's
  `input` (`promptInput()` threaded through all prompts). `src/index.ts` also pins columns/rows
  when a PTY reports 0 width (clack erase-lines otherwise OOMs at ~16GB).
- **Assets in the compiled binary**: `import.meta.dir` does not exist under `bun build
  --compile`; use `with { type: "file" }` imports (`items/claude-code/assets-embed.ts`).
- **Shell config**: per-item `zsh()` contributions assembled by `items/defs/shell-block.ts`
  (env → FPATH → compinit → init → aliases) into a managed `~/.zshrc` block; `doctor` reports gaps.
- **Ceremonies** (`src/ceremonies/handlers.ts`): attended steps by id (license pastes via
  clipboard, accessibility grant, Chrome web-app install via AX automation, GitHub device flow).
- **Release**: tag `v*` → `.github/workflows/release.yml` compiles darwin arm64/x64 with Bun
  embedded, attaches to the GitHub release; `install.sh` (served from `main`, deploys on merge)
  downloads `releases/latest`. CI (`ci.yml`) = check + tests + gitleaks.
- **Dev tooling**: Biome, markdownlint-cli2, lefthook, git-cliff, all no-Node. `bun run
  check|fix|test|compile|changelog`.

## Key empirical facts (hard-won; do not relearn)

- Interactive tests need a STRONG oracle (submit → next prompt appears). Kernel echo of keystrokes
  produced a false "input alive" once and shipped a broken release.
- Compiled binaries idle at ~160% CPU at any clack prompt (bun-run: 0%) — pre-existing
  bun-compile quirk, non-blocking, unfixed. Track upstream.
- `defaults read` truncates `-data` blobs; compare via `defaults export` XML base64.
- macOS symbolic hotkeys beat app registrations (CleanShot needed ids 28/30/184 disabled).
- `commit.gpgsign=true` with a missing key fails every commit; write it only once the key exists.
- GitHub token validity must be checked against the API (`gh auth status` ≠ envsetup's token).
- Release uploads can flake ("other side closed"); re-run the failed job, verify both assets.

## How to resume work

1. Orient: this file ("Status", "Next up") → [LEDGER.md](LEDGER.md) last section (what changed
   since the last release, and which files) → `git show <sha>` for anything you need in detail →
   PLAN.md only for the rationale behind a decision you are about to touch.
2. `git checkout main && git pull && bun install && bun run check && bun test` → read the "Next up"
item you are taking → branch `feat/…` or `fix/…` → conventional commits → PR → merge → release
per CONTRIBUTING.md (bump `package.json` + `src/index.ts` meta.version, `bun run changelog --
--tag vX.Y.Z`, tag, verify both assets). Peter approves outward-facing steps (push/PR/merge/
release) — ask once, then proceed with small separate commands (large compound commands get
denied by the permission prompt).
3. Before the PR is done: `bun run ledger`, fill in every placeholder (Summary, Why, a phrase per
   file — LEDGER.md has the template), `bun run ledger -- --check`, and update "Status" /
   "Next up" here if the picture changed — in the same PR.
